# Принципи програмування в проекті Ray Tracing Demo

У цьому документі описано основні принципи програмування, які були застосовані при розробці системи трасування променів.

## 1. Single Responsibility Principle (SRP) / Принцип єдиної відповідальності

Кожен модуль проєкту має чітко визначену зону відповідальності, що полегшує підтримку коду:

* [Модуль Window відповідає виключно за створення вікна, поверхні та Swapchain](./src/Window.cppm#L4).
* [Модуль UI ізолює всю логіку взаємодії з бібліотекою ImGui](./src/UI.cppm#L168).
* [ShaderController зосереджується лише на управлінні шейдерами та ресурсами GPU](./src/ShaderController.cppm#L74).

## 2. Separation of Concerns (SoC) / Розподіл обов'язків

Логіка рендерингу відокремлена від логіки інтерфейсу та завантаження даних:

* [Рендеринг сцени (Compute Pipeline) розділений на запис команд та малювання UI](./src/ShaderController.cppm#L157).
* [Завантаження та підготовка геометрії (побудова BVH) виконується модулем Engine](./src/Engine.cppm#L1).

## 3. Don't Repeat Yourself (DRY) / Не повторюйся

Повторювані операції Vulkan та операції з файлами винесені в утилітарні функції, що зменшує дублювання коду:

* [Універсальна функція для створення будь-яких типів буферів та виділення пам'яті](./src/ShaderController.cppm#L90).
* [Допоміжна функція для читання бінарних файлів шейдерів з диска](./src/ShaderController.cppm#L96).

## 4. Modularity / Модульність

Використання C++20 Modules дозволяє чітко контролювати видимість інтерфейсів та прискорює час компіляції:

* [Визначення експортованих функцій ядра рендерингу](./src/Engine.cppm)#L(1).
* [Контрольований імпорт залежностей між компонентами рендерінга](./src/ShaderController.cppm#L74).

## 5. Keep It Simple, Stupid (KISS) / Будь простішим

Використання сучасних стандартів C++ для спрощення коду та підвищення його читабельності:

* [Призначені ініціалізатори (Designated Initializers) для структур Vulkan](./src/Window.cppm#L35).
* [Використання std::span для безпечної та зручної передачі масивів даних до функцій](./src/ShaderController.cppm#L111).

## 6. Asynchronous Programming / Асинхронне програмування

Тривалі операції завантаження не блокують головний потік рендерингу:

* [Використання std::async та std::future для фонового завантаження 3D-моделей](./src/main.cpp#L127).
* [Атомарні прапорці для відстеження стану завантаження без гонки даних](./src/main.cpp#L211).
